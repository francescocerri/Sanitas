# Architecture Decision Records

Ogni file qui dentro documenta **una** decisione architetturale: il vincolo/problema che l'ha motivata, la decisione presa e le conseguenze. Solo la decisione presa, non le alternative scartate o il ragionamento di confronto tra opzioni — quello resta nella conversazione che l'ha prodotta, qui va solo l'esito. Si scrive un ADR quando si prende la decisione, non dopo — se una decisione cambia, si aggiunge un nuovo ADR che la supera, non si modifica quello vecchio (che resta come storia).

Template:

```markdown
# NNNN. Titolo della decisione

Status: Accettata | Superata da ADR-NNNN

## Contesto
Qual è il problema? Quali vincoli c'erano?

## Decisione
Cosa abbiamo deciso.

## Conseguenze
Cosa cambia, cosa si guadagna, cosa si perde, cosa resta aperto.
```
